Something Went Wrong

An ecommerce store where the error screen explains itself — built from telemetry the store is already sending to Dynatrace.

Medusa v2 + OpenTelemetry  ·  Dynatrace Grail, queried over MCP  ·  Gemini agent on Vertex AI Agent Engine

We can never account for every failing case

⚠️ Something went wrong. Please try again.
  • However advanced the software, some failure always slips through — and not every error can propagate cleanly to the frontend.
  • So the user is left in a dilemma: is it my fault? is it the system's? what should I do now?
  • Every unanswered "something went wrong" leaves a negative impression of the platform in the user's mind.

Comfort the user — with accurate information

  • Make it clear who is at fault: the user, the system, or both.
  • Make it clear what mitigates the situation right now: retry, fix the input, or wait.
  • Instead of a hope that it might work if tried just a moment later.

The answers already exist — in the exception the backend just caught, and in the telemetry already flowing into Dynatrace. They just never reach the user.

A store like any other

A decently made store application, receiving significant traffic, with Dynatrace observability already in place. A user fills a cart and goes to pay —

The causes can be many. The user doesn't know — and can't.

In comes the agent — ADK-built, Dynatrace-powered

It recognizes the failure immediately (the backend hands it the exception + the request's trace id) and answers twice:

Response 1 — comfort, immediately

From the failure info alone, no tools. States what failed and the consequence — e.g. "no charge was made" when the timeout happened before authorization.

lands in ~5 s · marked "first look"
Response 2 — the truth, investigated

Analyzes behind the scenes with Dynatrace: DQL against that exact trace, the failing span and stack, open Davis problems — many payment failures at the provider? an inventory issue?

lands in ~40 s · clearly says who is at fault

With that, the user can make a sound decision — and doesn't feel unsafe using the website.

Architecture — nothing here is mocked

The error path never waits on the agent — if the agent is down, the user sees the same error page as before. The agent only states what the telemetry shows; if the trace never appears, it says so.
